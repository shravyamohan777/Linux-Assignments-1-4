9) Compare init 0 and shutdown -h. Which is safer? Why?
ANS: shutdown -h is the safer command.

The difference is in their approach: one is a polite, systematic manager, and the other is an immediate directive.

? The process of shutting down

shutdown -h performs a step-by-step shutdown. It first sends a warning to all users, then politely asks all running services and processes to stop (using SIGTERM signals), waits for them to close files and finish tasks, cleanly unmounts filesystems, and only then tells the kernel to power off the hardware. It manages the entire sequence itself.

init 0 is a command that changes the system's runlevel to 0, which is defined as halt. This action triggers a set of scripts to stop services. However, it is generally more direct and is an instruction to switch to a halt state immediately.

? User notification

shutdown -h is designed with multi-user systems in mind. A key feature is that it broadcasts a message to all logged-in users, giving them time to save their work before the system goes down.

init 0 typically does not send a warning message to users. The shutdown process begins immediately, which can be disruptive and cause data loss for anyone actively working on the server.

? Flexibility and control

shutdown -h gives the administrator more control. You can schedule the shutdown for a future time (e.g., shutdown -h 23:00) or cancel a pending shutdown (shutdown -c). This flexibility is part of its safety-oriented design.

init 0 is an immediate command. Once executed, the process begins without an option for a scheduled delay or easy cancellation.


10) A system administrator accidentally powers off a Server machine without shutting it down properly. What problems can occur to the said Server? 

ANS: When a system administrator powers off a server without performing a proper shutdown, it is like pulling a plug. The server will be cut off mid operation, which can lead to several serious problems.
1. Data Corruption and Loss
This is the most immediate and severe risk. Any information stored in the computer's RAM that has not yet been permanently written to the hard drive is lost instantly. This can include:

? Unsaved documents that users were editing.

? Database corruption if a transaction was in progress, leaving data files in an inconsistent state.
? File system corruption, as the operating system may have been updating file structures. An abrupt stop can leave the file system inconsistent, leading to lost files or an unreadable disk.

2. Operating System Damage
 A sudden interruption can corrupt critical operating system files. The server might fail to boot correctly the next time, displaying errors or entering emergency recovery mode. Repairing this often requires time consuming recovery from a backup or a rescue disk.

3. Application and Service Failure
 Applications and services, such as web servers, email servers, or databases, are not given the opportunity to shut down cleanly. If they were writing to configuration files, logs, or temporary files, they could become unstable and fail to start correctly when the server is turned on again.

4. Hardware Risk 
In very rare cases, sudden power loss during a write operation can physically damage storage devices, especially older mechanical hard drives where the read/write head could crash onto the platters.
